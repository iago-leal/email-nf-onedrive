## Como publicar na VPS

A instalação foi feita por cópia, não por git, e `/opt/email-nf-onedrive` **não** é repositório.
O que funcionou hoje, da raiz do projeto:

```bash
git archive --format=tar.gz -o /tmp/email-nf.tar.gz <commit>
scp /tmp/email-nf.tar.gz medicina-leal:/tmp/
ssh medicina-leal
  sudo chown email-nf:email-nf /tmp/email-nf.tar.gz
  sudo -u email-nf tar xzf /tmp/email-nf.tar.gz -C /opt/email-nf-onedrive/app
  cd /opt/email-nf-onedrive/app && sudo -u email-nf /opt/email-nf-onedrive/.venv/bin/pip install --quiet .
  sudo -u email-nf /opt/email-nf-onedrive/.venv/bin/email-nf-onedrive --home /opt/email-nf-onedrive verificar-config
```

Use `git archive`, e não `tar` do macOS, que gera os arquivos `._*`. O `.env`, o `var/` e o
`autorizacoes/` ficam **fora** de `app/` e não são tocados pela extração.

## Como rodar ciclos sem depender da sessão

Duas tentativas anteriores morreram com código 255 quando o SSH caiu. O que resolveu:

```bash
sudo -u email-nf setsid nohup /tmp/observacao.sh > <log> 2>&1 < /dev/null &
```

O `/tmp/observacao.sh` é um laço de quatro ciclos, cada um parando sozinho no limite. Acompanhar
pelo log, nunca pela sessão aberta.

## Armadilhas apuradas, para não redescobrir

- O log da VPS está em **UTC**; os timestamps do registro também.
- O `testar-caixa` imprime no terminal e **não** grava no log: a conferência posterior se faz pelo
  `verificar-config`.
- Não há `sqlite3` de linha de comando na VPS; consulte pelo módulo do Python do venv.
- O `rclone` do usuário `email-nf` precisa de `HOME=/opt/email-nf-onedrive` para achar o `rclone.conf`.
- O `grep` por `enviado: ` no log não conta os `já existia idêntico: `, e os dois somam o número do
  resumo. Uma conciliação que ignore isso acusa divergência falsa.
